# 캐릭터 일관성 가이드

컷마다 얼굴이 달라지는 문제의 원인과 해결 절차. **이 문서의 규칙을 어기면 일관성은 반드시 깨진다.**

## 1. 왜 얼굴이 매번 바뀌었나

지금까지의 컷은 전부 **text2image**였다. 글로만 "민트색 아기 트리케라톱스, 복숭아색 뿔 세 개…"라고
쓰고 생성했다는 뜻이다.

글은 캐릭터를 고정하지 못한다. 같은 문장을 넣어도 모델은 매번 그 설명을 만족하는 **새로운 캐릭터를
새로 디자인**한다. 눈 간격, 주둥이 길이, 프릴 각도, 뿔 두께는 문장에 적혀 있지 않으므로 매번 다르게
나온다. 설명을 아무리 길게 써도 마찬가지고, 오히려 길수록 연출 지시가 묻힌다.

**seed도 해결책이 아니다.** seed는 *같은 모델 + 완전히 같은 프롬프트*를 재현할 때만 의미가 있다.
컷마다 프롬프트가 다르므로 seed를 고정해도 얼굴은 고정되지 않는다. `characters.json`의 seed는
같은 컷을 다시 뽑을 때 쓰는 재현용 번호일 뿐이다.

## 2. 해결책 — 캐릭터를 지정해서 생성한다

캐릭터를 고정하는 방법은 하나뿐이다. **생성할 때마다 그 캐릭터를 지정하는 것.**
방법은 두 가지이고, 1번이 훨씬 강하다.

### 방법 A — OpenArt Characters (권장)

OpenArt에 캐릭터를 등록하면 **트리거 워드**(고유 이름)를 받는다. 프롬프트에 그 이름을 쓰면
어떤 장면·구도·조명에서도 같은 얼굴로 렌더링된다. 플랫폼이 정체성을 잡아 주므로 우리가
레퍼런스를 매번 첨부할 필요가 없다.

등록은 이미지 1장으로도 되고, 여러 장을 넣으면 더 정확해진다. 기존 공식 3D 시트가 그 재료다.

**적용 절차**

1. `prompts/characters.json`의 각 캐릭터 `trigger`에 등록한 트리거 워드를 넣는다
   (현재는 한글 이름 그대로 — `쿵쿵` `루카` `후안` `미미` `티니` `루비`)
2. `python3 scripts/build_ref_prompts.py --episode ep1`
3. 60컷의 `image_ref`가 트리거 워드로 바뀐다. 그대로 붙여넣어 생성하면 된다

```
trigger 넣기 전:  Luca the tiger cub stepping forward with his goggles pushed back up...
trigger 넣은 뒤:  루카 stepping forward with his goggles pushed back up...
```

### 방법 B — 마스터 시트 첨부 (폴백)

캐릭터를 등록하지 않았거나, 등록한 캐릭터가 계속 흔들려 다시 만들어야 할 때.
캐릭터당 아래 두 장을 만들어 `reference/sheets/`에 넣고, 컷마다 `cast`에 적힌 시트를
전부 레퍼런스로 첨부한다.

1. **다각도 시트** — `characters.json`의 `master_sheet_prompts.turnaround`
2. **표정 시트** — `.expressions`

정면 한 장만으로는 옆·뒷모습 컷에서 무너지므로 다각도가 필요하다. 이 시트들은 캐릭터를
**재등록**할 때의 입력으로도 그대로 쓴다.

`trigger`가 비어 있으면 `build_ref_prompts.py`가 자동으로 이 방식(`ref_tag`)으로 생성하고
경고를 찍는다.

## 3. 반드시 지킬 규칙

**규칙 1 — 레퍼런스를 붙였으면 외모를 글로 다시 쓰지 않는다.**

이게 가장 많이 하는 실수다. 레퍼런스를 붙여 놓고 프롬프트에 또 "민트색 피부에 복숭아색 뿔 세 개…"를
쓰면, 모델은 이미지와 글 사이에서 **글을 따라 새로 그린다.** 레퍼런스가 있을 땐 이름으로만 부르고
(`Kung-Kung the baby triceratops`) 나머지는 **동작·표정·카메라·조명**만 쓴다.

트리거 워드를 쓸 때도 똑같다. 트리거 워드와 외모 서술이 함께 있으면 **서술이 이겨서**
등록된 캐릭터가 밀려난다.

`shots_v2.json`의 `image_ref`가 이 형태로 다시 쓰여 있다. 기존 `image`(외모 서술 포함)는
`build_ref_prompts.py`의 입력이자 폴백으로 남겨 두었지만, **실제 작업에는 `image_ref`를 쓴다.**

평균 프롬프트 길이가 200단어대에서 72단어로 줄었다. 연출 지시가 외모 설명에 묻히지 않는다.

**규칙 2 — 직전 컷을 레퍼런스로 쓰지 않는다. 항상 고정축으로 돌아간다.**

SC3-07의 결과를 SC3-08의 레퍼런스로 쓰는 식으로 이어 붙이면 오차가 **누적**된다. 20컷 뒤엔 완전히
다른 캐릭터가 된다. 매번 등록된 캐릭터(방법 A) 또는 마스터 시트(방법 B)로 돌아간다.

**규칙 3 — 영상 단계에서도 얼굴은 무너진다.**

image2video는 키프레임을 움직이면서 얼굴을 뭉갠다. 완화 방법:

- 클립을 짧게 유지한다 (현재 전 컷 4~5초, 의도된 설계다)
- 한 컷 안에서 고개를 180도 돌리는 연출을 넣지 않는다 — 뒤통수를 모델이 지어내야 하므로 반드시 깨진다
- 클로즈업일수록 잘 버틴다. 얼굴이 중요한 컷(SC3-08, SC3-17, EN-01)은 클로즈업으로 잡혀 있다
- 결과가 뭉개지면 그 컷만 다시 뽑는다

**규칙 4 — 의상·소품도 캐릭터의 일부다.**

루카의 고글, 미미의 금테 안경, 후안의 빨간 방울모자, 루비의 귀 리본과 별 지팡이, 쿵쿵이의 꽃무늬
반다나. 이것들이 빠지거나 색이 바뀌면 시청자는 다른 캐릭터로 인식한다. 검수 항목에 포함한다.

## 4. 검수 체크리스트

컷을 받을 때마다 확인한다.

| 항목 | 보는 것 |
|---|---|
| 얼굴 | 눈 크기·간격, 주둥이 길이, 볼 홍조 위치 |
| 머리 구조 | 쿵쿵 — 뿔 3개 길이와 각도, 프릴의 스캘럽 개수 |
| 배색 | 민트/크림 경계, 복숭아색 등 스큐트 줄 |
| 의상·소품 | 규칙 4의 목록 |
| 비율 | 머리 대 몸 비율, 다리 길이 |

두 개 이상 어긋나면 채택하지 말고 다시 뽑는다.

## 5. 참고 — 데이터 구조

`prompts/shots_v2.json`의 컷마다:

| 필드 | 용도 |
|---|---|
| `cast` | 이 컷에 등장하는 캐릭터. 방법 B에서는 첨부할 시트 목록이 된다. 비어 있으면 배경 컷 |
| `image_ref` | **실제로 쓰는 프롬프트.** 레퍼런스 전제, 외모 서술 없음 |
| `image` | 구 프롬프트(외모 서술 포함). 레퍼런스 없이 돌릴 때의 폴백 |
| `ko` / `ko_motion` | 한국어 컷 내용 |
| `motion` | 영상 단계 프롬프트 |

`prompts/characters.json`:

| 필드 | 용도 |
|---|---|
| `trigger` | OpenArt Characters 트리거 워드. 있으면 프롬프트에 이 이름이 들어간다 |
| `ref_tag` | `trigger`가 비었을 때의 폴백 호칭 |
| `sheet` | 마스터 시트 경로 |
| `consistency_tag` | 캐릭터 등장 컷 끝에 붙는 고정 지시문 |
| `master_sheet_prompts` | 방법 B의 마스터 시트 생성 프롬프트 |
| `desc` / `desc_short` | 구 text2image용 외모 서술. 레퍼런스 모드에서는 쓰지 않는다 |

## 6. 참고 — 이 방식으로 다시 만드는 법

`image_ref`와 `cast`는 손으로 고치지 말고 스크립트로 다시 만든다.

```bash
python3 scripts/build_ref_prompts.py --episode ep1
```

`characters.json`의 `trigger` / `ref_tag` / `style_tag` / `consistency_tag`를 바꾸면
60컷 프롬프트가 한 번에 따라온다.
