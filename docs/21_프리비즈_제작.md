# 21. 프리비즈 제작 — 블렌더로 먼저 찍고, 그다음 생성한다

## 왜 바꿨나

전에는 컷 설명을 곧장 생성기에 넣었다. 그러면 컷마다 카메라가 제멋대로 서고,
마음에 안 들어 다시 뽑으면 구도가 또 달라졌다. 앞뒤 컷이 안 붙는 이유의 대부분이
**연기가 아니라 카메라**였다.

그래서 순서를 바꾼다.

```
대본 → 프리비즈(블렌더) → 편집 → 확정 프레임 → 매핑 → 힉스필드 생성
```

구도·카메라·타이밍은 **블렌더가 정한다.** 생성기는 그 구도 위에 그림을 입히는
일만 한다. 컷 하나를 열 번 다시 뽑아도 구도는 그대로다.

## 무엇이 어디서 나오나

| | 어디서 | 왜 |
|---|---|---|
| **구도 · 카메라 · 렌즈** | **블렌더** | 손으로 보고 고칠 수 있어야 한다. 프롬프트로는 못 잡는다 |
| **컷 길이 · 타이밍** | **블렌더** | 전체를 재생해 봐야 길고 짧은 게 보인다 |
| **인물 배치** | **블렌더** | 누가 어디 서는지가 정해져야 시선이 맞는다 |
| 그림 · 재질 · 조명 | 생성기 | 프리비즈는 회색 덩어리다. 룩은 보지 않는다 |
| **화면 안 대사 · 그 컷 효과음** | **생성기** | 입모양을 맞추려면 생성 때 넣는 수밖에 없다 |
| 나레이션 · 환경음 · BGM · 자막 | 로컬 | 전과 같다 (`docs/17`) |

## 만드는 순서

### 1. 프리비즈를 만든다

```bash
python3 scripts/build_previz.py --episode ep1     # 한 화
python3 scripts/build_previz.py --all             # 40화 + 쇼츠 22편
```

`episodes/<ep>/previz/` 에 세 개가 나온다.

- `previz.json` — 컷마다 카메라(렌즈·거리·높이·움직임)와 인물 배치, 프레임 구간
- `블렌더_<ep>.py` — 블렌더 Scripting 탭에서 ▶ Run Script
- `프리비즈_작업지.md` — 컷 표. 무엇을 보고 무엇을 고칠지

카메라는 계산으로 잡는다. 샷 크기가 «주인공 키의 몇 배를 화면에 담을지» 를
정하고, 거기서 렌즈와 거리가 나온다.

| 샷 | 렌즈 | 담는 높이 | 키 1.6m 기준 거리 |
|---|---|---|---|
| 풀샷 WS | 24mm | 키의 3.0배 | 5.7m |
| 미디엄샷 MS | 50mm | 키의 0.62배 | 2.4m |
| 클로즈업 CU | 85mm | 키의 0.26배 | 1.7m |

여러 명이 한 화면에 있으면 좌우로 다 들어가도록 카메라가 더 빠진다.
키는 「캐릭터 키 도감」을 그대로 쓴다 — 루카 160 > 쿵쿵 140 > 루비 120 >
티니 110 > 미미 105 > 후안 100.

숫자를 바꾸려면 `bible/previz.json` 하나만 고친다. 전 화가 같이 바뀐다.

### 2. 블렌더에서 편집한다 — 여기가 진짜 연출이다

한 타임라인에 전 컷이 순서대로 깔리고, 컷마다 카메라가 **마커로 묶여 있다.**
스페이스바를 누르면 그 화가 통째로 재생된다.

- **타이밍부터 본다.** 구도는 그다음이다
- 마음에 안 드는 컷 → 그 마커로 가서 카메라를 옮긴다. N 패널에서 렌즈 mm 도 바꾼다
- 인물 위치 → 그 컷 프레임에서 옮기고 `I` → Location
- 컷 길이 → `shots_v2.json` 의 `duration` 을 고치고 `build_previz.py` 를 다시 돌린다

> **여기서 정한 카메라가 최종 카메라다.** 생성기는 이 구도를 따라 그리기만 한다.

카메라 움직임은 **대본이 «카메라» 라고 말한 컷에만** 붙는다. 나머지는 정지다.
인물이 «다가간다», 불티가 «카메라 옆으로 스쳐 간다» 를 카메라 움직임으로 잘못
읽으면 전 화가 흔들리기 때문이다. 움직임은 블렌더에서 사람이 넣는다.
대본이 둘을 같이 말한 컷은 작업지에 `⚠` 로 표시된다.

### 3. 프레임을 뽑는다

컷마다 **첫 프레임**과 **끝 프레임**을 PNG 로 뽑고 컷 ID 로 이름을 바꾼다.

```
SC2-10_시작.png
SC2-10_끝.png
```

### 4. 매핑한다 — 사람이 직접 건다

힉스필드에서 그 컷에 필요한 것을 건다.

| 슬롯 | 무엇을 |
|---|---|
| 캐릭터 | 등록해 둔 **캐릭터 마스터 시트**. 컷에 나오는 인물마다 하나씩 |
| 구도 | `<컷ID>_시작.png` |
| 끝구도 | `<컷ID>_끝.png` — 첫·끝 두 장으로 넣을 때만 |
| 배경 | 장면(SC) 단위 배경 레퍼런스. 같은 장면에서는 한 장을 계속 쓴다 |

> **자동으로 걸지 않는다.** 매핑은 사람이 보고 건다.

### 5. 엔진을 고르고 생성한다

| 컷 | 엔진 | 왜 |
|---|---|---|
| **대사가 있다** | **하이루(미니맥스)** | 한국어 입모양을 맞추는 건 여기뿐이다 |
| 대사 없고 카메라가 움직인다 | 힉스필드 내장 | 카메라 프리셋으로 프리비즈 움직임을 그대로 준다 |
| 대사 없고 물·불·연기·군중 | 클링 | 물리가 무거운 컷 |
| 그 외 | 하이루 | |

컷마다 어느 엔진인지 `제작_작업지.md` 에 이미 적혀 있다. 바꾸고 싶으면 **그 컷만**
바꾸면 된다 — 구도는 프리비즈가 들고 있으므로 앞뒤 컷은 다시 뽑지 않아도 된다.

엔진 표는 `bible/engines.json` 이다. 길이·입력 방식처럼 업체가 수시로 바꾸는
숫자에는 «확인» 이 달려 있다. 힉스필드 화면에서 실제 값을 보고 여기만 고친다.

## 프롬프트가 달라진 점

**카메라를 두 번 말하면 안 된다.** 프레임 두 장을 넣으면 카메라는 이미 거기
있는데, 프롬프트에까지 카메라 문장이 있으면 두 번 움직인다.

그래서 컷마다 두 벌이 나온다.

**첫·끝 두 장을 넣을 때** `권장` — `[카메라]` 줄이 없다

```
[구도] 첨부한 두 프레임이 첫 화면과 끝 화면이다. 그 사이만 움직인다. …
[외형] …
[연기] …
[대사] …
[소리] …
[화풍] …
```

**첫 장만 넣을 때** — `[카메라]` 줄이 붙는다

```
[구도] 첨부한 프리비즈 프레임의 구도를 그대로 따른다. …
[외형] …
[연기] …
[카메라] 카메라가 천천히 앞으로 밀고 들어간다.
[대사] …
[소리] …
[화풍] …
```

예전의 `[동작]` 이 **`[연기]` 와 `[카메라]` 로 갈라진 것**이 핵심이다.
`ko_motion` 에서 «카메라가 …» 처럼 **카메라가 주어인 구절만** 골라내
`[카메라]` 로 옮긴다. «파편이 카메라 옆으로 스쳐 간다» 는 카메라를 기준점으로만
쓴 연기 묘사라서 `[연기]` 에 남는다.

대사 컷은 여전히 **통째로 한국어**다. 영어 설명 안에 한글 대사만 끼워 넣으면
그 컷을 통째로 건너뛴다. 대사 없는 컷만 영어로 나간다.

## 막힐 때

- **카메라가 두 번 움직인다** — 두 장을 넣으면서 `[카메라]` 줄이 든 프롬프트를 썼다
- **구도가 프리비즈와 다르다** — `[구도]` 줄을 지웠거나 프레임을 안 걸었다
- **앞뒤 컷이 안 붙는다** — 프리비즈에서 두 컷의 카메라가 이어지는지 **먼저** 본다.
  프롬프트 문제가 아닐 때가 훨씬 많다
- **얼굴이 매번 달라진다** — 캐릭터 마스터 시트를 안 걸었다
- **대사를 안 한다** — 대사 컷을 하이루 아닌 엔진으로 보냈다

## 자동 생성

**지시가 있을 때까지 자동 생성하지 않는다.** 블렌더 MCP 로 장면을 만들고 힉스필드로
생성하는 것은 기술적으로 가능하지만, 크레딧이 나가는 일은 사람이 누른다.

`블렌더_<ep>.py` 도 아무것도 렌더하지 않고 아무것도 생성하지 않는다. 장면만 만든다.
